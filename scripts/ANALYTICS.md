# Яндекс Метрика — 113073211

Единый код: `assets/js/analytics.js`. Асинхронный tag.js, webvisor/clickmap/trackLinks/accurateTrackBounce включены, ssr и ecommerce:dataLayer сохранены. Счётчик работает на rugby2027.ru и www.rugby2027.ru; локальные копии, checks/ и вложенные iframe исключены из статистики. Внешний VK iframe не инструментируется.

Все публичные HTML-документы подключают один defer-скрипт. `scripts/sync_analytics.py` рекурсивно добавляет подключение и удаляет его дубли. `npm run build` запускает синхронизацию; `npm test` проверяет покрытие. При ручной публикации в корень main обязательно выполнить оба шага. Будущие страницы с общим menu.js также получают загрузчик автоматически. На GitHub Pages нет серверного автоматического внедрения в произвольный новый HTML: новый документ должен пройти эту сборку или подключить общий menu.js.

Глобальный флаг защищает повторное выполнение; проверяются уже загруженная библиотека, очередь init и готовый экземпляр счётчика. Не вставлять второй inline-счётчик. Без JS статистика не отправляется; отдельный noscript-пиксель не используется. Блокировка Метрики не ломает интерфейс.

## Цели в кабинете

В счётчике 113073211 открыть «Цели → Добавить цель → JavaScript-событие», условие «совпадает», создать:

| Идентификатор | Название | Когда отправляется |
|---|---|---|
| match_open | Открытие матча | Один раз на документ со SportsEvent JSON-LD |
| player_card_open | Фото игрока | После успешной загрузки и фактического открытия фото |
| balance_click | Переход к Балансу | Нажатие на существующую партнёрскую ссылку |
| support_click | Поддержка проекта | Открытие блока по ссылке/summary, нажатие на реквизиты или копирование |

Кабинетные цели не создаются кодом reachGoal. Их создание требует доступа владельца к Метрике. События уже реализованы в коде.

`match_open` передаёт match_id (SportsEvent @id), match_name, start_date: это различает матчи на постоянном /match-center/. При смене матча обновлять SportsEvent вместе с содержимым. Отдельные страницы используют тот же механизм. `player_card_open` дополнительно передаёт стабильный player_id. Карточки публикуют CustomEvent `rugby:player-open` в assets/js/player-cards.js. Для поддержки параметр action: open_link, open_details, requisites, copy_attempt. Последнее означает попытку копирования, а не подтверждённый перевод. Номер карты и содержимое буфера не передаются в параметрах целей.

Переходы не задерживаются ради аналитики. Закрытие карточки/неуспешная загрузка фото не дают цели. Общие просмотры страниц считает init; отдельный hit повторно не вызывается. Исторические редиректы могут не успеть отправить просмотр до перехода; целевая страница считается штатно.

Проверки: npm test; npm run build. На живом сайте проверить единственный tag.js, его data-loaded=true и появление yaCounter113073211; отсутствие доступа/блокировщик в проверочном браузере явно отметить. Доставку событий и Вебвизор окончательно смотреть в кабинете владельца.
