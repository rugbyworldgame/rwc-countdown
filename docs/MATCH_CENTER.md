# Матч-центр Rugby 2027

Реализовано 24 октября 2026. GitHub Pages публикует файлы из корня `main`.
Общая рекламируемая ссылка: https://rugby2027.ru/match-center/.

## Как устроено

- `data/matches.json` — единственный источник данных матчей. `matches` хранит все записи; `featured` — IDs матчей, которые сейчас показываем в верхней панели.
- `scripts/render_matches.py` — генератор готового HTML. `scripts/templates/match.html` — существующее оформление, меню, поддержка, «Баланс», Метрика.
- `match-center/<id>/index.html` — постоянная страница матча с собственными canonical, Open Graph и SportsEvent. Не редактировать вручную.
- `match-center/index.html` — общий вход, также генерируется. Без JavaScript показывает первый матч и обычные ссылки.
- `assets/css/match-selector.css` — компактная панель, две колонки на узких экранах.
- `assets/js/match-selection.js` — выбор при входе; `assets/js/match-clock.js` — таймер выбранного матча.

Обычные HTML-ссылки переключают страницу целиком. Предыдущий документ и его VK iframe выгружаются. В каждом документе ровно один iframe. Это намеренное решение: не нужны AJAX, несколько скрытых работающих плееров, повторная инициализация фото или Метрики. Работает Back/Forward и прямое открытие любой страницы. Автопереход только с общего входа при двух и более featured; постоянные страницы никогда не перенаправляются. Один featured — нет панели и автоперехода.

## Добавление матча

1. Добавить объект в `matches`, скопировав структуру существующего. Новый `id`: `YYYY-MM-DD-home-away` латиницей. ID после публикации не менять.
2. `start`: ISO 8601 с явным `+03:00`; `competition`, `season`, `round`, `venue`, `city`, `country` (ISO 2) — проверенные сведения.
3. `home`/`away`: name, текстовый badge, hex color, players. Игроки перечисляются по номерам 1–23: 15 стартовых, 8 запасных. Не ставить предположительные составы. Если подтверждения нет, `players: []`: появится аккуратное пояснение.
4. `video`: только полный src предоставленного iframe VK; не весь HTML. Генератор сохраняет fullscreen, разрешения и 16:9. Каждому матчу свой URL.
5. `introTitle`, `intro`: короткий текст, без HTML; генератор экранирует ввод.
6. `officials`: referee, assistants, tmo. Неизвестные поля — null или отсутствуют; выводится «Пока не подтверждено».
7. `sources`: массив объектов label/url с источниками заявок и судей. Проверять даты и туры. Для состава «Лейнстера» 24.10.2026 использована публикация RTÉ; веб-версия официального сайта не отдала текст заявки. Остальные заявки проверены по клубам/LNR.
8. Добавить ID в `featured`. Для нового дня заменить только featured; прежние объекты оставлять в matches. Архивные страницы остаются доступны, их ссылки находятся под основным содержимым. Сам генератор ничего не удаляет.
9. Выполнить `npm run matches:sync`, `npm test`, `npm run build`. Публиковать JSON, генератор/шаблон при их изменении, весь изменённый сгенерированный HTML и sitemap. GitHub Pages не запускает npm автоматически: готовый HTML должен быть в коммите.
10. После деплоя проверить `/match-center/` и все новые постоянные URL, iframe src/hash, составы, Метрику, поддержку и партнёра.

## Автовыбор и продолжительность

`status`: scheduled (по умолчанию), live (подтверждено вручную), finished, postponed, cancelled.
При входе сначала выбирается явно live; иначе последний начавшийся за последние 3 часа; иначе ближайший будущий; иначе последний из доступных. Временное окно в 3 часа используется лишь для выбора, не для объявления завершения. При пересечении расписаний выбирается наиболее поздно начавшийся, предыдущий остаётся доступен одним нажатием. Для известной длительной задержки можно поставить live. Настоящий статус VK плеера сайт не читает: cross-origin API для этого не подключено.
После старта надпись «Время начала по расписанию прошло · включайте плеер», без ложного утверждения о фактическом ходе игры. Завершение отображается только при status=finished. Во время просмотра никаких автоматических переключений/удалений матчей нет. Даже если расписание сдвинулось, зритель выбирает любую подготовленную трансляцию сам.

## Игроки и существующие функции

Общая база фото остаётся `assets/players/players.json`, изображения `/assets/players/`. Имена сопоставляются с name/aliases; можно указать `{ "name": "Имя (капитан)", "playerId": "stable-id" }`. Генератор автоматически добавляет data-player-id для известных имён (включая подпись капитана). Неизвестный игрок остаётся обычным текстом без пустой карточки. Фото не копируются в отдельные базы матчей.

Карточки, меню, кнопка вверх, поддержка и аналитика используют прежние скрипты. На постоянной странице Метрика берёт match_id из её SportsEvent. Переход к другому матчу — новое открытие страницы и отдельная цель match_open. Общая база игроков и партнёрская ссылка не менялись.

## Проверки

`check_matches.py`: один iframe, соответствие видео/даты/команд, отсутствие дублирующихся IDs, составы 15+8, сохранение поддержки/аналитики, режим одного матча и отсутствие неизвестных данных.
`check_match_selection.mjs`: время до матча, пересечение, задержка свыше 2 часов, live/finished/postponed и один матч.
`render_matches.py --check`: сгенерированный HTML соответствует JSON и шаблону.
Общие проверки SEO теперь включают постоянные страницы из sitemap. `seo_sync.py` передаёт создание матчей генератору вместо устаревшей записи одного SportsEvent.
